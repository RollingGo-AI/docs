## v2.9 (2026-10-22)

### 🚀 Core Update: Stateless Search Pagination Mechanism

* **Stateless Pagination Token (`nextPageToken`)**:
  * Added `nextPageToken` in `searchHotels` response. Callers can pass this token in multi-turn conversations when requesting "next batch" or pagination to explore candidate hotels continuously.
* **Dynamic Page Size (`size`)**:
  * Supports custom hotel count per page (default: 5, flexibly configurable from 1 to 10).
* **Anti-Drift Parameter Snapshot**:
  * Paged requests automatically inherit the initial query's destination, dates, stars, and price filters, preventing LLM parameter drift during multi-turn interactions.
* **Incremental Availability Probing**:
  * The server utilizes real-time incremental probing, returning immediately upon matching target inventory, significantly reducing multi-turn pagination latency.

## v2.8 (2026-10-16)

### 💳 Core Update: Multi-Platform Checkout & Payment Routing

* **Mutually Exclusive Payment Payload by Host Environment**:
  * Returns **`paymentUrl`** (Web checkout string) for web and browser environments.
  * Returns **`miniProgramPayInfo`** (Native checkout object) for WeChat Mini Program or mobile native environments.
  * Strictly mutually exclusive based on host environment, eliminating payload confusion.
* **Safe Nulling for Non-Pending States**:
  * For orders that are confirmed, cancelled, or expired past the 30-minute window, the payment field is safely set to `null` to prevent broken navigation.
* **Standardized Payment Tools**:
  * Synchronously upgraded `createHotelBookingWithPaymentURL`, `getHotelOrderDetail`, and `searchHotelOrders` to maintain uniform payment data structures.

## v2.7 (2026-09-20)

### 🔄 Core Update: Two-Phase Post-Booking Order Cancellation

* **Added Dedicated Cancellation Tools**:
  * Added **`preCancelHotelBooking`** (pre-cancellation & penalty calculation) to obtain a 10-minute valid token `confirmId`.
  * Added **`confirmCancelHotelBooking`** (confirm & execute cancellation), requiring a valid `confirmId` to prevent accidental cancellations.
* **Lightweight Cancellation for Unpaid Orders**:
  * Unpaid orders (`Booked`) can be directly cancelled within seconds without redundant downstream calls.
* **Multi-Language Policy Output**:
  * Cancellation policies and guidance natively support English, Chinese, and Japanese dynamic adaptation.

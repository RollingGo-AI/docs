## v2.9 (2026-10-22)

### 🚀 核心更新：酒店搜索无状态分页机制

* **新增无状态翻页凭证 (`nextPageToken`)**：
  * 在 `searchHotels` 返回结果中新增 `nextPageToken`，调用方在多轮对话中“换一批”或翻页时，传入该 Token 即可继续向后探索候选酒店。
* **动态每页数量 (`size`)**：
  * 支持自定义每页返回的酒店数量（默认为 5 家，支持 1~10 家灵活配置）。
* **参数防漂移快照**：
  * 翻页请求自动继承首轮对话的地点、入住退房日期、星级与价格筛选快照，有效避免大模型多轮交互时产生条件漏传或参数漂移。
* **增量查价优化**：
  * 服务端采用实时增量探测机制，命中目标数量立即响应，大幅缩短多轮翻页延迟。

## v2.8 (2026-10-16)

### 💳 核心更新：收银台与支付链路多端适配

* **支付形态按宿主环境互斥下发**：
  * 针对 Web/浏览器环境，返回网页支付直链 **`paymentUrl`**；
  * 针对微信小程序或移动端原生环境，返回原生拉起收银台对象 **`miniProgramPayInfo`**；
  * 两者根据环境二选一严格互斥下发，杜绝调用端字段混淆。
* **非待支付状态安全置空**：
  * 针对已支付、已取消或超过 30 分钟支付时效的订单，支付字段统一安全置为 `null`，避免客户端跳转失效链接。
* **支付核心 Tool 统一规范**：
  * 同步升级 `createHotelBookingWithPaymentURL`（创建订单）、`getHotelOrderDetail`（订单详情）与 `searchHotelOrders`（订单列表），保证支付数据结构在全流程中的严格一致。

## v2.7 (2026-09-20)

### 🔄 核心更新：售后订单取消两阶段能力闭环

* **新增订单取消核心工具**：
  * 新增 **`preCancelHotelBooking`**（预取消与罚金试算），获取具备 10 分钟时效的取消凭证 `confirmId`；
  * 新增 **`confirmCancelHotelBooking`**（确认并执行取消），必须携带有效 `confirmId` 才能执行不可逆取消，杜绝误触。
* **未支付订单轻量直接关闭**：
  * 针对未扣款的待支付订单，支持秒级直接取消，不产生冗余下游调用。
* **多语言退改政策输出**：
  * 取消规则与提示文案原生支持中文、英文、日文多语言动态适配。

## v2.6 (2026-08-24)

### 🌍 核心更新：多币种、多语言与房型精细化筛选

* **规范多语言多币种入参 (`localeParam`)**：
  * 国际版统一支持 `localeParam: { currency, language }`，支持 USD、EUR、JPY、HKD、GBP 等 25+ 种国际主流货币报价。
* **房型高级筛选 (`filter`)**：
  * `getHotelDetail` 接口支持免费取消（`cancelPolicy`）与含早餐（`mealType`）条件过滤，帮助 Agent 快速匹配用户个性化需求。
* **参数规范清理**：
  * 全面清理并废弃了早期历史冗余参数，字段命名更具语义化。
